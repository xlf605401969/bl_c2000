# Bootloader协议文档

## 概述
本文档描述了基于Modbus的简化型引导加载程序协议，用于通过会话状态机制更新主MCU及其从MCU的固件。该协议使用标准Modbus RTU功能码0x04进行寄存器读取，并使用自定义功能码0x65-0x69进行引导加载程序操作。通过引入会话状态机制，擦除、编程、复位等操作变为通用的，根据当前会话状态自动操作本地MCU或指定的从MCU。超时管理统一由上位机实现，不需要协议层处理。

### 地址映射
引导加载程序使用直接地址空间来管理本地和远程闪存操作：

#### 地址空间布局
| 地址范围 | 描述 |
|---------|------|
| 0x080000-0x087FFF | 主MCU引导加载程序（受保护） |
| 0x088000-0x0B7FFF | 主MCU APP (192KB) - 本地闪存 |
| 0x000000-0x03FFFF | 从MCU1 APP (256KB) - 远程闪存 |
| 0x000000-0x03FFFF | 从MCU2 APP (256KB) - 远程闪存 |

#### 会话机制
通过会话状态机制确定操作的目标设备：
- 当会话目标为本地MCU时，使用本地MCU地址空间 (0x088000-0x0B7FFF)
- 当会话目标为从MCU时，使用从MCU地址空间 (0x000000-0x03FFFF)

## 功能细节

### 功能码0x04 - 读输入寄存器
从寄存器读取引导加载程序信息。

**请求**：
```
[从站地址][0x04][起始地址高位][起始地址低位][寄存器计数高位][寄存器计数低位][CRC低位][CRC高位]
```

**响应**：
```
[从站地址][0x04][字节计数][数据...][CRC低位][CRC高位]
```

**支持的寄存器范围**：
- 0xF000-0xF00F: 引导加载程序核心信息
- 0xF100-0xF10F: 闪存信息
- 0xF300-0xF3FF: 应用程序信息（包括Git标签）

**限制**：
- 单次读取最多64个寄存器
- 超出范围的寄存器返回0x0000

### 功能码0x65 - 进入引导加载程序模式
将设备切换到引导加载程序模式。

**请求**：
```
[从站地址][0x65][CRC低位][CRC高位]
```

**响应**：
```
[从站地址][0x65][状态][CRC低位][CRC高位]
```

状态：
- 0x00 = 成功
- 0xFF = 失败

### 功能码0x66 - 擦除闪存
按指定地址范围擦除闪存内存。

**请求**：
```
[从站地址][0x66][起始地址(4字节)][长度(4字节)][CRC低位][CRC高位]
```

特殊命令：起始地址=0xFFFFFFFF，长度=0xFFFFFFFF 擦除整个APP区域

**响应**：
```
[从站地址][0x66][状态][实际起始地址(4字节)][实际长度(4字节)][CRC低位][CRC高位]
```

状态：
- 0x00 = 成功
- 0x02 = 地址超出范围
- 0x03 = 擦除失败
- 0xFF = 未知错误

### 功能码0x67 - 写入闪存
将数据写入指定地址的闪存内存。

**请求**：
```
[从站地址][0x67][地址(4字节)][长度高位][长度低位][数据...][CRC低位][CRC高位]
```

**响应**：
```
[从站地址][0x67][状态][已写字节数高位][已写字节数低位][CRC低位][CRC高位]
```

状态：
- 0x00 = 成功
- 0x02 = 地址超出范围
- 0x04 = 写入失败
- 0x05 = 地址未对齐
- 0xFF = 未知错误

说明：
- 数据长度以字节为单位，但FLASH操作以16位字为单位（会自动转换）
- 当目标地址位于app_info区域(0x088000-0x08803F)时，数据会被缓存到RAM中而非直接写入FLASH
- app_info缓存会在功能码0x6A执行时写入FLASH
- 如果数据跨越app_info区域边界，超出部分会正常写入FLASH
- 最大单次写入长度受LWMB_RX_MAX_LENGTH限制

### 功能码0x68 - 刷新FLASH缓存
将FLASH缓冲区全部写入FLASH。

**请求**：
```
[从站地址][0x68][CRC低位][CRC高位]
```

**响应**：
```
[从站地址][0x68][状态][CRC低位][CRC高位]
```

状态：
- 0x00 = 成功
- 0x04 = 写入失败
- 0xFF = 未知错误

### 功能码0x69 - 跳转到应用程序
跳转到指定地址的应用程序代码。

**请求**：
```
[从站地址][0x69][跳转地址(4字节)][CRC低位][CRC高位]
```

跳转地址：应用程序入口地址 (0xFFFFFFFF = 默认地址)

**响应**：
```
[从站地址][0x69][状态][CRC低位][CRC高位]
```

状态：
- 0x00 = 成功
- 0x01 = 无效应用程序（当跳转地址为0xFFFFFFFF但app_info.valid_flag无效时）
- 0xFF = 未知错误

说明：
- 当跳转地址为0xFFFFFFFF时，会检查当前app_info的valid_flag
  - 如果valid_flag有效，则跳转到app_start_addr
  - 如果valid_flag无效，返回0x01错误状态
- 当跳转地址为其他值时，实际跳转地址会被设置为app_start_addr（忽略传入的地址）
- **当前实现中跳转功能尚未完全实现（代码中标记为TODO）**，会返回成功响应但不会实际跳转

### 功能码0x6A - 完成APP写入
完成APP写入操作并更新app_info信息。

**请求**：
```
[从站地址][0x6A][CRC低位][CRC高位]
```

**响应**：
```
[从站地址][0x6A][状态][CRC低位][CRC高位]
```

状态：
- 0x00 = 成功
- 0x04 = 写入失败
- 0x06 = 无应用程序信息（未写入app_info或校验失败）
- 0xFF = 未知错误

说明：
- 该功能码会先执行flush操作，确保所有缓存数据写入Flash
- 检查app_info缓存是否有效（即是否通过功能码0x67向app_info区域写入过数据）
- 如果缓存无效，返回0x06错误状态，但不会执行后续写入操作
- 如果缓存有效，校验魔数(0xDEADBEEF)：
  - 校验通过：设置valid_flag为0xAA55，返回0x00成功状态
  - 校验失败：返回0x06错误状态
- **无论校验是否通过，都会将缓存数据写入Flash的app_info区域**
- 写入后会再次执行flush操作确保数据持久化

### 功能码0x70 - 设置会话目标
设置当前会话操作目标，切换flash_mgr实际操作的对象。

**请求**：
```
[从站地址][0x70][目标类型][CRC低位][CRC高位]
```

目标类型：
- 0x00 = 本地MCU (BL_PROTO_TARGET_LOCAL_MCU)
- 0x01 = 从MCU1 (BL_PROTO_TARGET_SLAVE_MCU1)
- 0x02 = 从MCU2 (BL_PROTO_TARGET_SLAVE_MCU2)

**响应**：
```
[从站地址][0x70][状态][CRC低位][CRC高位]
```

状态：
- 0x00 = 成功
- 0x02 = 目标类型无效
- 0xFF = 未知错误

说明：
- 切换目标后会自动激活指定的flash管理器
- 同时更新app_start_addr为BL_APP_START_ADDR(0x088000)
- 更新app_max_size为目标flash管理器的整个flash大小（通过get_size()获取）
- 会重新读取对应目标的app_info信息

目标映射：
- BL_PROTO_TARGET_LOCAL_MCU(0x00) -> flash_mgr[0] (本地Flash)
- BL_PROTO_TARGET_SLAVE_MCU1(0x01) -> flash_mgr[1] (CM Flash)
- BL_PROTO_TARGET_SLAVE_MCU2(0x02) -> flash_mgr[1] (CM Flash，与MCU1共用)

### 功能码0x75 - 重置设备
重置设备。

**请求**：
```
[从站地址][0x75][CRC低位][CRC高位]
```

**响应**：
```
[从站地址][0x75][状态][CRC低位][CRC高位]
```

状态：
- 0x00 = 成功
- 0xFF = 未知错误

注意：当前实现中复位功能尚未完全实现（代码中标记为TODO），响应会返回成功状态但实际不会执行复位操作

## 寄存器映射

### 0xF000-0xF00F: 引导加载程序核心信息
| 地址 | 名称 | 类型 | 描述 |
|-----|------|------|------|
| 0xF000 | BL_MAGIC | uint16 | 引导加载程序魔数 (0xBEEF = 引导加载程序模式) |
| 0xF001 | BL_VERSION | uint16 | 引导加载程序版本（高位字节=主版本，低位字节=次版本） |
| 0xF002 | BL_STATE | uint16 | 引导加载程序状态 |
| 0xF003 | BL_CAPABILITY | uint16 | 能力位图 (0x0001 = 支持本地MCU编程) |
| 0xF004 | BL_ERROR_CODE | uint16 | 最后错误代码 |

### 0xF100-0xF10F: 闪存信息
| 地址 | 名称 | 类型 | 描述 |
|-----|------|------|------|
| 0xF100-0xF101 | FLASH_SIZE | uint32 | 闪存总大小（以16位字为单位） |
| 0xF102-0xF103 | FLASH_APP_START | uint32 | 应用程序起始地址 |
| 0xF104-0xF105 | FLASH_APP_MAX_SIZE | uint32 | 应用程序最大大小（以16位字为单位） |

### 0xF300-0xF30F: 应用程序信息
| 地址 | 名称 | 类型 | 描述 |
|-----|------|------|------|
| 0xF300 | APP_INFO_VALID_FLAG | uint16 | app_info结构体有效标志 (0xAA55 = 有效) |
| 0xF301-0xF302 | APP_INFO_ENTRY_ADDR | uint32 | 应用程序入口地址(高位-低位) |
| 0xF303 | APP_MAJOR_VERSION | uint16 | 应用程序主版本号 |
| 0xF304 | APP_MINOR_VERSION | uint16 | 应用程序次版本号 |
| 0xF305-0xF306 | APP_INFO_APP_START_ADDR | uint32 | 应用程序起始地址(高位-低位) |
| 0xF307-0xF308 | APP_LENGTH | uint32 | 应用程序实际长度（字节，高位-低位） |
| 0xF309-0xF30A | APP_CRC32 | uint32 | 应用程序CRC32校验码(高位-低位) |
| 0xF30B-0xF30C | APP_TIMESTAMP | uint32 | 应用程序构建时间戳(高位-低位) |
| 0xF30D-0xF30E | APP_GIT_COMMIT_ID | uint32 | Git提交ID(高位-低位) |
| 0xF30F | APP_GIT_TAG_LENGTH | uint16 | Git标签长度(字节数) |

### 0xF310-0xF3FF: Git标签信息
| 地址 | 名称 | 类型 | 描述 |
|-----|------|------|------|
| 0xF310+ | APP_GIT_TAG | uint8[] | Git标签字符串(变长，长度由0xF30F指定) |

**验证规则说明：**
- **app_info结构体有效性**：通过magic number (0xDEADBEEF) 验证，APP_INFO_VALID_FLAG寄存器反映此状态
- **应用程序有效性**：通过valid_flag (0xAA55) 验证，表示应用程序本身是否有效
- 两个标志位独立验证，分别指示不同层面的有效性

## 更新流程

### 本地MCU更新
1. 进入引导加载程序模式：发送功能码0x65
2. 擦除闪存：发送功能码0x66，地址=0xFFFFFFFF擦除整个APP区域
3. 写入固件：发送功能码0x67，以数据块形式发送固件数据
4. 写入app_info结构体（可选）：使用功能码0x67向app_info区域写入数据
5. 完成APP写入：发送功能码0x6A（会自动执行flush操作）
6. 跳转到应用程序：发送功能码0x69，地址=0xFFFFFFFF

**注意**：
- 如果需要更新应用程序，必须在步骤4中写入app_info结构体（包含魔数0xDEADBEEF），否则步骤5会返回0x06错误
- 即使返回错误，缓存数据仍会被写入Flash
- 只有当app_info魔数校验通过时，valid_flag才会被设置为0xAA55

### 从MCU更新
1. 进入引导加载程序模式：发送功能码0x65
2. 设置会话目标：发送功能码0x70，目标类型=0x01（从MCU1）或0x02（从MCU2）
3. 擦除闪存：发送功能码0x66，地址=0xFFFFFFFF擦除整个APP区域
4. 写入固件：发送功能码0x67，以数据块形式发送固件数据
5. 写入app_info结构体（可选）：使用功能码0x67向app_info区域写入数据
6. 完成APP写入：发送功能码0x6A（会自动执行flush操作）
7. 切换回本地MCU：发送功能码0x70，目标类型=0x00（如需）
8. 跳转到应用程序：发送功能码0x69，地址=0xFFFFFFFF

**注意**：
- 如果需要更新应用程序，必须在步骤5中写入app_info结构体（包含魔数0xDEADBEEF），否则步骤6会返回0x06错误
- 即使返回错误，缓存数据仍会被写入Flash
- 只有当app_info魔数校验通过时，valid_flag才会被设置为0xAA55
