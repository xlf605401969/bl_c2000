# Bootloader 上位机使用示例

## 示例1：烧录主MCU固件

### 准备工作

1. 准备固件文件：
   - `firmware_low.hex` - 低字节HEX文件
   - `firmware_high.hex` - 高字节HEX文件

2. 连接硬件：
   - 将C2000开发板通过USB转串口连接到PC
   - 确认设备管理器中显示COM口（如COM3）

### 操作步骤

1. **启动应用**
   ```bash
   npm start
   ```

2. **配置串口**
   - 串口：选择 `COM3`
   - 波特率：`250000`
   - 从站ID：`1`

3. **选择目标**
   - 选择"主MCU (C2000, 16位内存)"

4. **选择文件**
   - 点击"浏览"选择 `firmware_low.hex`
   - 点击"浏览"选择 `firmware_high.hex`

5. **配置版本**（可选）
   - 主版本：`1`
   - 次版本：`2`
   - 构建号：`100`

6. **开始烧录**
   - 点击"开始烧录"
   - 等待进度条完成
   - 查看日志确认成功

## 示例3：使用快捷操作

### 进入Bootloader模式

有时需要手动让设备进入Bootloader模式：

1. 配置串口参数
2. 点击"进入Bootloader"按钮
3. 等待操作完成

### 跳转到应用程序

烧录完成后，如果需要手动启动应用：

1. 配置串口参数
2. 点击"跳转到应用"按钮
3. 设备将运行应用程序

### 查看系统信息

读取设备上完整的系统信息：

1. 配置串口参数
2. 点击"查看系统信息"按钮
3. 弹出窗口显示三大类信息：

**Bootloader信息：**
- 魔数（0xBEEF表示Bootloader模式）
- BL版本号
- 运行状态
- 能力位图（支持的功能）
- 最后的错误码

**Flash信息：**
- Flash总容量
- APP起始地址
- APP最大容量

**应用程序信息：**
- 有效标志（0xAA55表示有效）
- 版本号（主版本.次版本）
- 入口地址和起始地址
- 应用程序长度
- CRC32校验码
- 构建时间戳
- Git提交ID和标签

**提示：** 这些信息是在固件编译时写入HEX文件的，烧录后可以通过此功能验证版本和完整性。

## 示例4：查看设备系统信息

### 检查完整的设备信息

可以一次性查看设备的Bootloader、Flash和应用程序的完整信息：

1. **连接设备**
   - 设备可以在应用程序模式或Bootloader模式

2. **配置串口**
   - 串口：选择对应COM口
   - 波特率：`250000`
   - 从站ID：`1`

3. **查看信息**
   - 点击"查看系统信息"按钮
   - 等待读取完成

4. **验证信息**
   - **Bootloader魔数**：0xBEEF表示Bootloader模式
   - **BL版本**：如 `v1.0`
   - **能力位图**：显示支持的功能
   - **Flash容量**：总容量和可用容量
   - **APP有效标志**：应显示 `0xAA55 ✅ 有效`
   - **APP版本号**：如 `v1.2`
   - **CRC32**：用于完整性校验

### 使用场景

**场景1：烧录前验证**
- 检查设备当前状态（Bootloader模式还是应用模式）
- 查看当前固件版本
- 判断是否需要更新
- 确认Flash容量是否足够

**场景2：烧录后验证**
- 确认设备已正确进入应用模式
- 验证新固件版本号
- 通过CRC32验证固件完整性
- 检查是否有错误码

**场景3：故障诊断**
- 查看Bootloader错误码
- 判断是否卡在Bootloader模式
- 检查Flash配置是否正确
- 验证应用程序有效性

**场景4：批量设备管理**
- 记录每个设备的固件版本
- 追踪Git提交ID
- 管理固件发布
- 生成设备清单

## 示例5：批量烧录

如果需要烧录多个设备：

1. 烧录第一个设备（按上述步骤）
2. 断开第一个设备
3. 连接第二个设备
4. 点击刷新串口按钮
5. 选择新的串口
6. 点击"开始烧录"（文件路径会保留）

## 示例6：加载 HEX2 组合文件

仓库中提供了一个可直接用于界面验证的示例文件：

- `examples/sample_bundle.hex2`
- `examples/sample_cpu1_appinfo.hex2`
- `examples/sample_multi_target_demo.hex2`

建议的验证步骤：

1. 启动应用
2. 在“固件来源”中选择“HEX2组合文件”
3. 点击浏览并选择 `examples/sample_bundle.hex2`
4. 在“目标选择”中切换 `主MCU`、`CM核`、`CPU2`
5. 观察“内存浏览器”中的目标切换、地址范围和逐字节内容是否变化
6. 切换到自定义目标 `config`，确认只浏览不烧录的行为是否符合预期

说明：

- 该示例主要用于验证 HEX2 解析、多目标拆分和内存浏览器显示。
- 其中 `cpu2` 与 `config` 目标当前用于查看和解析，不建议用于实际烧录。

## 示例7：验证固件 AppInfo 弹窗

仓库中提供了一组专门用于验证 CPU1 AppInfo 的示例文件：

- `examples/sample_cpu1_appinfo_low.hex`
- `examples/sample_cpu1_appinfo_high.hex`
- `examples/sample_cpu1_appinfo.hex2`

建议的验证步骤：

1. 启动应用
2. 选择以下任一方式加载固件：
   - 传统 HEX：选择 `sample_cpu1_appinfo_low.hex` 和 `sample_cpu1_appinfo_high.hex`
   - HEX2：选择 `sample_cpu1_appinfo.hex2`
3. 点击“查看固件AppInfo”按钮
4. 保持地址为 `0x088000`
5. 点击“解析CPU1 AppInfo”
6. 确认弹窗中显示以下字段：
   - Magic：`0xB16B00B5`
   - 有效标志：`0xAA55 (有效)`
   - 版本：`v1.7`
   - 起始地址：`0x00088040`
   - 长度：`256`
   - Git Tag：`sample-appinfo-demo`

说明：

- 该弹窗当前固定只解析 CPU1 对应区域。
- 这个示例适合回归验证 AppInfo 弹窗、HEX2/传统 HEX 兼容性，以及地址读取逻辑。

## 示例8：验证多目标 HEX2 烧录与浏览

若需要同时验证 CPU1、CM、CPU2 和自定义段，可使用：

- `examples/sample_multi_target_demo.hex2`

该示例包含：

- `cpu1`：带 AppInfo 的主固件镜像
- `cm`：CM 示例镜像
- `cpu2`：CPU2 示例镜像
- `config`：仅供浏览的自定义配置段

建议的验证步骤：

1. 在“固件来源”中选择“HEX2组合文件”
2. 选择 `examples/sample_multi_target_demo.hex2`
3. 在“目标选择”中切换当前查看目标，确认内存浏览器内容变化
4. 点击“查看固件AppInfo”，确认仍能在 CPU1 的 `0x088000` 位置读到 AppInfo
5. 在“烧录目标”区域多选 `CPU2`、`CM核`、`主MCU`
6. 观察启动烧录时的目标顺序应为 `CPU2 -> CM -> CPU1`

## 常见场景

### 场景1：固件更新

更新已有设备的固件：

1. 设备上电
2. 使用"进入Bootloader"进入烧录模式
3. 选择新固件文件
4. 开始烧录
5. 烧录完成后自动跳转到应用

### 场景2：首次烧录

新设备首次烧录：

1. 确保设备处于Bootloader模式
2. 配置串口和选择固件
3. 开始烧录
4. 完成后设备自动运行

### 场景3：双核烧录

同时更新主MCU和CM核：

1. 先烧录主MCU固件：
   - 选择"主MCU"
   - 选择主MCU固件文件
   - 开始烧录

2. 再烧录CM核固件：
   - 选择"CM核"
   - 选择CM核固件文件
   - 开始烧录

## 故障排查

### 问题1：找不到串口

**解决方法：**
- 检查USB线缆连接
- 检查设备驱动是否安装
- 点击刷新按钮
- 在设备管理器中查看COM口状态

### 问题2：烧录失败

**解决方法：**
- 检查串口参数是否正确
- 确认固件文件路径正确
- 尝试降低波特率
- 查看日志了解详细错误
- 重新进入Bootloader模式

### 问题3：进度卡住

**解决方法：**
- 点击"停止"按钮
- 检查设备连接
- 重启应用
- 重新开始烧录

## 高级配置

### 调整数据块大小

默认64字节，可根据通信质量调整：

- 通信良好：可增大到128或256字节（更快）
- 通信不稳定：可减小到32或16字节（更稳定）

### 版本号管理

建议的版本号规则：

- **主版本号**：重大更新或不兼容变更
- **次版本号**：功能添加或改进
- **构建号**：Bug修复或小改动

示例：
- `1.0.0` - 初始版本
- `1.1.0` - 添加新功能
- `1.1.1` - 修复Bug（构建号+1）
- `2.0.0` - 重大更新

## 性能优化

### 提高烧录速度

1. 使用更高波特率（如500000）
2. 增大数据块大小（如128或256）
3. 使用质量好的USB线缆
4. 减少后台程序干扰

### 提高稳定性

1. 使用推荐波特率（250000）
2. 使用默认数据块大小（64）
3. 确保USB供电充足
4. 避免在烧录过程中操作其他程序
